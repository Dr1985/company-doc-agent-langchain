 # Phase 3 要做的事情

> 目标：把现有 `src/agent` 的对话能力接上“文档检索 + 引用来源”，做成可用的基础问答闭环。
>
> 本阶段只做后端 RAG 核心，不包含前端（前端单独算 Phase 3.5）。

## 1. Phase 3 的核心目标

- [ ] 用户提问后，系统能返回基于知识库的答案
- [ ] 答案必须来自检索到的文档片段，不能凭空编造
- [ ] 回答结果里要带上引用来源（文档名 / chunk / 相似度）
- [ ] 当知识库没有足够相关内容时，系统要明确拒答或说明“未检索到足够资料”

## 2. 需要补的后端能力

### 2.1 RAG 主流程

- [ ] 在现有 `src/agent/workflow.py` 流程中接入文档检索结果
- [ ] 用户提问时，先检索相关 chunk，再把检索结果送给 LLM
- [ ] 保留现有 LangGraph / tool-call / long-term memory 机制，不重写整套 agent

### 2.2 检索能力

- [ ] 接入 `src/retrieval/retriever.py` 到问答主流程
- [ ] 实现向量相似度检索结果的整理与排序
- [ ] 补上 BM25 关键词检索
- [ ] 实现混合检索融合策略（向量 + BM25）
- [ ] 支持元数据过滤（如部门、文档类型、日期、标签）
- [ ] 支持 chunk 命中后回溯父文档上下文

### 2.3 回答与引用

- [ ] 设计 RAG prompt，让模型只根据检索资料回答
- [ ] 设计引用编号规则（例如 `[1] [2]`）
- [ ] 返回 `sources` / `citations` 给前端展示
- [ ] 在结果中保留文档名、chunk 序号、内容摘要、score 等信息

### 2.4 接口层

- [ ] 让 `src/interface/interaction.py` 支持基础问答的完整输出
- [ ] 保持 `/chat` 作为主入口
- [ ] 如有必要，补充一个返回检索结果与答案的统一响应结构

## 3. Phase 3 的交付物

- [ ] 单轮问答可用
- [ ] 文档检索可用
- [ ] 回答带来源可追溯
- [ ] 无相关资料时可拒答
- [ ] 后端链路可稳定跑通并可测试

## 4. Phase 3 明确不做的事情

- [ ] 不做 Vue 3 前端页面（这个算 Phase 3.5）
- [ ] 不做 Redis 热点问答缓存（Phase 4）
- [ ] 不做 OCR、表格提取、Rerank、自动分类、摘要、相似文档推荐（Phase 5）
- [ ] 不做管理后台和知识图谱（Phase 6）

## 5. 推荐实施顺序

- [ ] 第一步：把检索结果接入问答链路
- [ ] 第二步：让回答带来源、带拒答机制
- [ ] 第三步：补测试，覆盖“无结果 / 多结果 / 过滤文档 / 异常”场景
- [ ] 第四步：稳定后再进入 Phase 3.5 做前端
