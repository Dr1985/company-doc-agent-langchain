t # Phase 3 要做的事情

> 目标：把现有 `src/agent` 的对话能力接上"文档检索 + 引用来源"，做成可用的基础问答闭环。
>
> **开发原则：先做 Vue 3 页面原型，确认后再做后端 API**，前后端视为同一阶段的整体交付。

## 1. Phase 3 的核心目标

- [ ] 用户提问后，系统能返回基于知识库的答案
- [ ] 答案必须来自检索到的文档片段，不能凭空编造
- [ ] 回答结果里要带上引用来源（文档名 / chunk / 相似度）
- [ ] 当知识库没有足够相关内容时，系统要明确拒答或说明"未检索到足够资料"

## 2. 前端 — Vue 3 页面原型

> **原则：先产出页面原型 / 交互稿，确认后再实现对应的后端 API。**

### 2.1 P0：登录 / 会话页

- [ ] 登录表单（用户名 + 密码）
- [ ] 注册表单
- [ ] 登录后展示用户 token 信息、过期时间
- [ ] 会话列表（创建 / 切换 / 删除会话）
- [ ] 当前会话高亮标识

### 2.2 P0：问答页（聊天框 + 引用来源 + 历史区）

- [ ] 聊天消息列表（区分用户消息 / AI 消息）
- [ ] 消息输入框 + 发送按钮（支持 Enter 快捷发送）
- [ ] 同步回答模式
- [ ] 流式回答模式（SSE 逐字输出）
- [ ] AI 回答底部展示引用来源（文档名、chunk 摘要、相似度）
- [ ] 点击引用来源可展开查看详细 chunk 内容
- [ ] 历史消息回看（当前会话内）
- [ ] 清空当前会话按钮
- [ ] 拒答提示样式（当知识库无相关内容时）

### 2.3 P1：文档选择侧栏 / 结果预览区

- [ ] 已入库文档列表（展示文档状态、chunk 数、更新时间）
- [ ] 文档就绪 / 处理中 / 失败 状态标识
- [ ] 可勾选文档以限定检索范围
- [ ] 未就绪文档灰显不可选
- [ ] 选中文档后问答仅检索所选文档

## 3. 需要补的后端能力

### 3.1 RAG 主流程

- [ ] 在现有 `src/agent/workflow.py` 流程中接入文档检索结果
- [ ] 用户提问时，先检索相关 chunk，再把检索结果送给 LLM
- [ ] 保留现有 LangGraph / tool-call / long-term memory 机制，不重写整套 agent

### 3.2 检索能力

- [ ] 接入 `src/retrieval/retriever.py` 到问答主流程
- [ ] 实现向量相似度检索结果的整理与排序
- [ ] 补上 BM25 关键词检索
- [ ] 实现混合检索融合策略（向量 + BM25）
- [ ] 支持元数据过滤（如部门、文档类型、日期、标签）
- [ ] 支持 chunk 命中后回溯父文档上下文

### 3.3 回答与引用

- [ ] 设计 RAG prompt，让模型只根据检索资料回答
- [ ] 设计引用编号规则（例如 `[1] [2]`）
- [ ] 返回 `sources` / `citations` 给前端展示
- [ ] 在结果中保留文档名、chunk 序号、内容摘要、score 等信息

### 3.4 接口层

- [ ] 让 `src/interface/interaction.py` 支持基础问答的完整输出
- [ ] 保持 `/chat` 作为主入口
- [ ] 补充统一的响应结构（检索结果 + 答案 + 引用来源）
- [ ] `POST /auth/login` — 用户登录
- [ ] `POST /auth/session` — 创建会话
- [ ] `GET /auth/sessions` — 获取会话列表
- [ ] `GET /documents/documents` — 文档列表
- [ ] `GET /documents/documents/{doc_id}` — 文档详情（状态、chunk 数、更新时间）
- [ ] `POST /documents/retrieve` — 文档检索
- [ ] `POST /chatbot/chat` — 同步问答
- [ ] `POST /chatbot/chat/stream` — 流式问答
- [ ] `GET /chatbot/messages` — 获取会话消息历史
- [ ] `DELETE /chatbot/messages` — 清空会话消息
